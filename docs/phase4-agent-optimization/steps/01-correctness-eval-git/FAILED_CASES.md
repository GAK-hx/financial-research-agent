# Step 01 失败与修复记录

## 1. Docker 构建网络中断

- 现象：首次下载 PyTorch 元数据时出现 `SSL record layer failure`；
- 分类：网络/供应商下载错误，不是代码或依赖解析错误；
- 修正：Docker 中 `PIP_DEFAULT_TIMEOUT` 从 120 秒提高到 240 秒，重试从 5 次提高到 10 次；
- 结果：复用缓存后镜像构建成功。

## 2. LangGraph 等价测试动态 ID

- 现象：首次全量测试 149 项中 1 项失败；
- 原因：摘要与风险现在也引用带 Run 前缀的 Evidence ID，旧测试只忽略 claims，错误地比较了
  两次独立运行的动态 ID；
- 修正：等价测试保留完整报告结构，只归一化各自 Run ID 前缀；
- 结果：全量测试通过。

## 3. Ruff CI 初始配置不可用

- 现象：最新版 Ruff 对历史代码报告 134 个风格与现代化告警；
- 原因：CI 未显式固定第一版 lint 规则，导致本步引入即必红；
- 修正：先建立 `E4/E7/E9/F` 正确性基线，并清理 6 个真实未使用导入；
- 结果：`ruff check src tests` 通过。更广泛风格治理不与框架正确性改造混做。

## 4. Flash 综合报告数值方向变体

- 问题：`综合分析贵州茅台最近一年的股价表现、趋势指标和机构观点`；
- 首次 Run：`fac19edc74dd42369e479c28022b4ef1`；
- Planner：模型成功；语义对齐：通过；Evidence：7 条；
- 初稿及一次修订后的最终错误：

```text
summary:NUMERIC_UNSUPPORTED:11.2572%
summary:NUMERIC_UNSUPPORTED:23.4679%
risk[0]:NUMERIC_UNSUPPORTED:23.0%
```

报告表达为“股价下跌 11.2572%”“最大回撤 23.4679%/超过 23%”，Evidence 存储为
`-11.2572%` 和 `-23.4679%`。这两种写法在金融语义上等价，原 Validator 缺少“下跌”和
“回撤幅度”的方向归一化。

- 修正：补充方向词规则、回撤幅度等价和小数显示容差；新增专项确定性测试；同时要求
  `report_v3` 对摘要数字执行同样的 Evidence 约束；
- 复测 Run：`8327ae6560f74586a95b554e868551cd`；
- 结果：一次生成通过，`validation.passed=true`，无修订，47.603 秒。

该修复不是放宽任意数字：仍要求同一节引用的 Evidence 中存在对应数值，只对方向表达和
显示精度做有上下文的等价处理。
