# Step 01：正确性、评测与 Git 基线

## 1. 目标

在增加新能力前修复现有系统会“形式通过但语义错误”的问题，并建立后续所有修改都能复现、
比较和安全提交的基线。

## 2. 范围

### 2.1 生产时钟与评测时钟分离

- 移除 Compose 中应用和 Job 服务的固定 `EVALUATION_REFERENCE_DATE` 默认值；
- 生产请求默认使用真实当前日期；
- 只有评测命令显式传入参考日期，并与冻结数据集的 `as_of_date` 一致；
- 在 Run 元数据中同时记录执行时间、业务参考日期、时区和数据最大可用日期；
- 为“最近一个完整交易日/月/季/年”建立统一解析规则和交易日历边界。

### 2.2 原问题与 QuerySpec 语义对齐

新增独立的 `SemanticAlignmentResult`，至少检查：

- 股票实体没有丢失、替换或无依据增加；
- 相对日期解析保持原有粒度，例如“完整交易月”不能解析成自然年；
- 指标的单位、窗口、复权、同比/环比和截面/时序含义一致；
- 用户要求的分析域均进入计划，未要求的域不会被悄然扩大；
- 不确定表达进入澄清/限制，而不是被静默猜测。

失败时在 Tool 执行前停止，返回结构化原因；低风险可确定表达才允许规则化解析。

### 2.3 报告与 Evidence 对齐

- 将摘要、关键结论、风险、数据限制改为结构化段落；
- 每条定量结论必须关联 Evidence ID 和 Source Locator；
- 每条风险标记为“事实”“确定性计算”或“模型解释”；
- Validator 检查数字、日期、实体、单位、方向和来源，不只检查是否存在引用；
- 综合分析 Skill 必须要求与声明能力相符的行情、财务和/或研报证据；
- 无可靠证据时输出 `insufficient_evidence`，不能用常识补成事实。

### 2.4 版本化评测环境

- 生成可冻结的行情、财务、研报元数据和知识快照 Manifest；
- 把开发回归题和私有 Holdout 分开，Holdout 不进入 Prompt、示例和开发日志；
- 增加语义对齐、时间解析、证据支撑、轨迹重复、恢复率、成本和延迟指标；
- 保留错误题的原始输入、原始模型输出、解析结果、Trace、重试和最终分类；
- LLM Judge 只评估语言和开放性解释，确定性事实仍由规则判定。

### 2.5 Git 与交付准备

- 首次提交前轮换所有曾在对话或日志中暴露的 API Key；
- 初始化 Git，完善 `.gitignore`，排除 `.env`、Lake、模型缓存、密钥、运行产物和受版权保护 PDF；
- 将 Compose 的研报目录从相邻旧项目改为本仓库 `./data/reports`；
- 增加 Secret 扫描、基础 lint/单测和无需真实 API 的离线 CI；
- 先创建私有 GitHub 仓库；公开前单独审核代码、数据许可、PDF/研报版权和历史记录；
- 不把真实模型 API 测试设为每次 CI 的强制任务。

### 2.6 模型策略落地

- `config.py`、`.env.example`、README 和操作命令默认使用 `deepseek-v4-flash`；
- 所有角色默认 Flash，不做 Pro 自动路由或隐式回退；
- 历史 Pro 报告保留并注明是旧版本基线；
- 新增模型决策记录，后续换模型必须显式修改配置并生成新的评测基线。

## 3. 交付物

- 语义对齐和时间解析模型/Validator；
- Evidence 支撑关系和报告结构升级；
- 版本化评测 Manifest、开发回归与私有 Holdout 规则；
- Git/CI/Secret/数据许可说明；
- 更新后的 Compose、README、`.env.example` 和运行手册；
- `EVIDENCE.md`、失败案例文件和 Gate 报告。

## 4. 测试安排

开发中仅做一个时间表达和一个报告引用的最小冒烟。Step 收尾统一执行：

1. 确定性单元与集成测试；
2. Docker 全量回归；
3. 真实 Flash 开发回归与私有 Holdout；
4. 网络/供应商错误重试与失败产物检查；
5. Secret 扫描和干净仓库启动验证。

## 5. Gate

- 时间、实体、量纲、权限、伪造引用等 P0 用例 100%；
- 原问题到 QuerySpec 的语义对齐用例 100%；
- 所有定量结论和关键风险的 Evidence/Source Locator 覆盖 100%；
- 综合模型题集不低于 95%，剩余失败有明确分类且不是 P0；
- 生产未设置评测日期时使用真实当前日期；
- 仓库不含 Key、`.env`、版权 PDF、Lake 数据和本地模型缓存；
- Docker 不依赖 `../financial-agent` 才能启动。

## 6. 停止条件

- 时间/语义错误仍能通过 Validator；
- 需要把私有题集或真实 Key 放入仓库才能运行；
- 报告结论无法追溯到 Evidence；
- 干净环境无法构建或数据来源许可不明。
