# Step 02：知识、RAG、记忆与上下文闭环

## 1. 目标

建立“外部事实如何进入系统、如何被检索、如何进入上下文、哪些内容可以长期保留”的完整链路。
本步不增加开放自主性，先保证知识和记忆可信、可追溯、可删除。

## 2. 范围

### 2.1 离线事件知识流水线

建立独立后台工作流：

```text
来源适配 → 游标/高水位 → 原始载荷落 Iceberg
→ 标准化 → 去重 → 股票实体关联 → 事件结构化
→ CANDIDATE → 来源/时间/证据校验 → ACTIVE 或 REJECTED
→ 检索索引与版本更新
```

首批只选择能稳定提供 `source_id/url`、`published_at`、正文和股票实体依据的来源。来源尚未
确认时先完成协议和本地样例，不把不可靠接口包装成实时新闻能力。

事件记录至少包含：

- `event_id`、`symbol`、`event_type`；
- `event_time`、`published_at`、`ingested_at`、`available_at`；
- `source_id`、`source_url`、`source_rank`、`content_hash`；
- `raw_version`、`extraction_version`、`status`；
- `evidence_refs`、`supersedes`、冲突和拒绝原因。

同一事件允许多个来源；检索结果必须保留来源差异，不能在入库时把冲突“平均”掉。

### 2.2 RAG 升级

- 文档按标题、章节、表格和段落进行结构化分块；
- 使用父子 Chunk：子块负责命中，父块提供完整上下文；
- 增加关键词检索，与 BGE Dense Retrieval 通过 RRF 合并；
- 股票、日期、文档类型、来源和版本作为过滤字段；
- 支持增量新增、内容更新、失效删除和索引重建审计；
- Reranker 仅在 A/B 评测证明收益后启用，避免先增加延迟和资源；
- 将行情/财务精确查询、事件检索、研报检索作为不同路由，不用一个向量库包办。

### 2.3 记忆分层

#### 工作记忆

复用 LangGraph Checkpoint，保存当前问题、计划、Tool 结果、Evidence Manifest、预算和节点进度。
大对象保存引用，避免 Checkpoint 无限制膨胀。

#### 情节记忆

保存已验证的任务结果和失败策略，如“某日期表达需要交易日历解析”。只在 Run 终态且验证通过后
写入；检索时按任务类型、Skill 版本、模型版本和时间过滤，不能把旧结论当作当前事实。

#### 程序记忆

保存版本化 Skill 包、流程、示例和校验规则。模型只能选择已发布版本，不能把一次生成内容直接
写成 ACTIVE Skill。

#### 偏好记忆

只保存用户明确确认的报告长度、风险展示和对比偏好；实施租户/用户隔离、TTL、删除和审计。

#### 语义事实

公司事件和外部事实属于知识层，不写入会话偏好表。知识可被多个会话共享，但必须带来源、时效、
状态和冲突信息。

### 2.4 记忆操作和治理

实现并区分 `write/read/update/reflect/forget`：

- 写入前判断类型、来源、置信度、租户和有效期；
- 更新不覆盖历史版本，保留替代关系；
- Reflect 只提取已验证的失败模式或稳定偏好；
- 遇到冲突时向 Context 暴露冲突，不静默选择；
- 定时清理过期 Session 和记忆，合并重复情节；
- 提供查看、删除和禁用记忆的管理接口。

本步不建立“记忆 Agent”。目标漂移由确定性约束守卫检查，记忆整理由后台任务完成。

### 2.5 Context Builder 与压缩

Context Builder 根据原问题、Skill 和当前节点构造分层 Context Manifest：

1. 不可变系统策略与原始目标；
2. 当前计划、进度、预算和待解决缺口；
3. 与本节点有关的 Evidence 和知识；
4. 相关偏好、已验证情节和程序说明；
5. Tool Schema 与输出格式。

每一项记录来源、版本、选择/裁剪原因、估算 Token 和原始引用。输入预算预留 20%～30% 给输出；
超限时先删低相关重复项，再使用确定性摘要，最后才调用 Flash 生成摘要。数字、日期、引用和
Source Locator 必须保留。稳定前缀保持顺序一致，以利用服务商可能提供的前缀缓存。

## 3. 存储责任

| 内容 | 存储 |
|---|---|
| 原始/标准化文档和事件 | Iceberg |
| 事件状态、游标、版本、Lineage | PostgreSQL |
| 向量和检索字段 | Milvus + 关键词索引 |
| Checkpoint、情节和偏好 | PostgreSQL |
| Skill 文件与 Manifest | Git 管理的项目目录 + 发布元数据 |

## 4. 交付物

- 事件/文档 Schema、来源适配协议和状态机；
- 离线知识流水线、恢复游标和幂等写入；
- 混合 RAG、增量索引和检索评测；
- 分层 Memory API、治理任务和审计接口；
- Context Manifest、预算器和压缩策略；
- Docker 任务、操作说明、失败案例和 Gate 报告。

## 5. 测试安排

开发中只做一条样例事件入库、一次检索和一次记忆隔离冒烟。Step 收尾统一测试：

- 重跑、断点恢复、重复载荷和版本更新；
- `CANDIDATE` 不可被在线报告当作有效知识；
- Recall@K、NDCG、引用正确率、Faithfulness 和延迟；
- 记忆跨用户隔离、TTL、删除、冲突和过期事实拒用；
- Context 超限、压缩、Evidence 保真和实际 Usage 校准；
- 真实 Flash 端到端知识问答与失败场景。

## 6. Gate

- 知识采集重跑无重复有效记录，断点后可恢复；
- 未通过校验的 Candidate 进入正式报告为 0；
- 所有知识结论保留 URL/来源、时间、版本和 Evidence；
- 混合检索在冻结集上不低于当前 Dense 基线，新增复杂度有实测收益；
- 跨用户记忆泄漏为 0，过期/冲突事实不会被静默当作当前事实；
- 压缩前后数字、日期、实体和 Source Locator 保留率 100%；
- 模型综合题集不低于 95%，P0 项 100%。

## 7. 停止条件

- 来源无法提供可验证的发布时间或出处；
- 检索索引被当作事实源且无法回溯原文；
- 记忆与知识仍共用模糊的无类型记录；
- 压缩会覆盖或丢失原始 Evidence；
- 为运行流水线必须加入明显超出当前资源预算的新基础设施。
