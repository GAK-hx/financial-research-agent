# 进度记录规则

## 1. 每步两个文件

- `PLAN.md`：实施前冻结的范围、任务、交付物和验收标准；
- `PROGRESS.md`：实施期间唯一的事实进度记录。

PLAN变更必须记录原因，不能为了匹配已经写出的代码而静默修改验收标准。

## 2. 状态定义

- `NOT_STARTED`：计划已存在但未编码；
- `IN_PROGRESS`：至少一个任务在做；
- `BLOCKED`：存在无法继续的明确阻塞；
- `IN_REVIEW`：交付物完成，等待验收；
- `COMPLETED`：所有必需验收通过且证据已记录。

## 3. Progress必须包含

- 当前状态和完成度；
- 任务清单；
- 已产生文件/接口/表；
- 测试命令和结果；
- 数据或截图等验收证据；
- 阻塞、风险和未解决问题；
- 决策引用；
- 按日期追加的工作日志。

## 4. 验收证据原则

“代码已写”不是验收证据。有效证据包括：测试输出、数据行数与抽样、Schema、API响应、评测结果、资源统计和明确的人工审核结果。

## 5. 完成度

完成度按必需清单项计算，不按主观估计。可选项不影响步骤完成，但必须记录是否延期。
