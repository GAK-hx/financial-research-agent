# 第一阶段总实施计划

## 1. 阶段目标

完成一个使用真实日线、财务数据和证券研报的单次研究任务闭环。模型负责问题理解、有限规划和报告表达；程序负责数据管理、工具执行、指标计算、Evidence构建和校验。

## 2. 完成后的用户路径

```text
POST /analyze
→ 识别股票、日期、意图
→ 生成并校验任务计划
→ 并行查询行情/财务/研报
→ 确定性计算指标
→ 构建Evidence
→ 生成结构化报告
→ 校验数字、实体、日期和引用
→ 返回report + evidence + validation + timings
```

## 3. 实施顺序

```text
01 设计规范确认
  ↓
02 数据管理基础
  ├──→ 03 行情日线 → 04 行情/指标工具 ──┐
  ├──→ 05 财务数据/工具 ────────────────┤
  └──→ 06 研报知识库/检索 ──────────────┤
                                        ↓
                                07 Agent编排
                                        ↓
                              08 Evidence/报告/校验
                                        ↓
                              09 API/基础可观测
                                        ↓
                              10 测试/评测/验收
```

步骤03、05、06在步骤02完成后可以并行设计或实现，但步骤07开始前，至少Market、Indicator、Report Search三个工具必须完成。Financial Tool可在无法获得稳定字段时降级为受限能力，但必须明确状态，不能空实现注册。

## 4. 阶段里程碑

### Gate A：设计规范确认

- 领域模型、Namespace、工具名单和Evidence Schema审核通过；
- 数据口径、复权口径和第一版股票池确认；
- 未决策项写入DECISIONS。

### Gate B：真实数据可用

- 日线、基础财务和研报Metadata具有真实数据；
- 数据批次、质量结果和来源可追踪；
- Simulation不进入正式查询。

### Gate C：工具可独立运行

- 每个工具脱离LLM可测试；
- 输入、输出、超时、错误和数据来源明确；
- 指标由代码计算。

### Gate D：Agent闭环

- 标准问题生成合法计划；
- 工具执行结果转换为Evidence；
- 报告只引用本次Run的Evidence；
- 错误引用和关键数字错误被拦截。

### Gate E：阶段验收

- `/analyze`三条标准路径通过；
- 20题最小评测集完成；
- 已知限制、资源和真实指标写入README；
- 所有步骤Progress包含验收证据。

## 5. 第一阶段范围

### 包含

- Run、Working、Evidence三类单次任务记忆；
- 日线、基础财务、研报三个真实数据域；
- 固定白名单只读工具；
- 规则兜底和结构化模型Planner；
- 有限并行、超时、重试和一次修订；
- 同步API及基础阶段状态；
- 离线测试和最小评测。

### 不包含

- Session/长期记忆；
- 完整Workspace、进程级恢复；
- 多Agent；
- 动态工具/MCP；
- 交易、告警或写操作；
- ClickHouse、HDFS、MinIO、Kubernetes；
- 完整Harness和在线评测。

## 5.1 Docker优先实施原则

- App、Milvus、Etcd均通过Docker Compose运行；
- 日线采集、财务采集、RAG索引、质量检查和评测使用一次性容器；
- Iceberg Warehouse、Catalog、Milvus和任务产物使用命名卷或明确挂载目录；
- 宿主机只运行`docker compose`及管理脚本，不作为Python运行环境；
- 各步骤验收优先记录容器内执行命令和结果；
- 需要快速单元测试时可以在容器内运行`pytest`，避免宿主机环境差异。

| 项目 | 默认值 |
|---|---:|

| 工具调用 | 8 |

| 研报Evidence | 10 |

## 7. 步骤完成规则

每一步必须同时满足：

1. PLAN中的交付物存在；
2. 必需测试通过；
3. 验收证据写入该步骤PROGRESS；
4. 阻塞项已关闭或被接受为已知限制；
5. 相关架构决策已更新；
6. 审核状态改为Accepted。

## 8. 阶段风险

- AkShare字段变化：使用映射层和接口一致性测试；
- Iceberg SQLite并发：第一阶段单写者；
- 财务字段复杂：先冻结最小指标集；
- BGE维度差异：运行时探测；
- 模型结构化输出失败：Pydantic校验和规则兜底；
- 报告幻觉：Evidence-only输入和代码Validator；
- 计划过度复杂：标准轨迹优先、最多6任务。
