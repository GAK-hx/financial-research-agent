# FinQA 复杂子集 B/C/D 报告

## 评测设置

从公开 FinQA `dev` split 中选择官方程序至少包含两个连续操作的题目，排除此前使用的5道
Canary 题后，按原始顺序冻结前20题。清单只包含 case_id、程序步数和入选原因，不包含答案、
Gold Program 或证据内容。

三个配置均使用 DeepSeek V4.1 Flash、相同公开上下文、相同的6,251条公开 `train` 程序 Skill
和 FinQA 官方评测器。评测 split 的 Gold 只用于离线选层和最终评分，不进入推理。

## 官方结果

| 配置 | Execution Accuracy | Program Accuracy | 推理成功率 |
|---|---:|---:|---:|
| B 单Agent | 30% | 20% | 100% |
| C 固定表格+计算团队 | 50% | 35% | 100% |
| D 动态Supervisor团队 | 55% | 40% | 100% |

相对单 Agent，固定团队 Execution / Program 分别提升20 / 15个百分点；动态团队分别提升
25 / 20个百分点。说明多步财务程序题中，表格理解、计算程序、受控执行和Evaluator闭环有正增量。

动态团队只比固定团队高5个百分点。20题、单次运行不足以区分真实增量和模型生成波动，不能据此
宣称 Supervisor 优于固定团队。

## 成本与行为

| 配置 | 平均研究Agent | 平均模型调用 | 平均工具调用 | 平均Token | 定向修复 |
|---|---:|---:|---:|---:|---:|
| B 单Agent | 1.00 | 1.00 | 0.00 | 1,688 | 0 |
| C 固定团队 | 2.00 | 4.40 | 4.30 | 9,883 | 4 |
| D 动态团队 | 1.95 | 5.35 | 4.30 | 10,917 | 4 |

动态团队比固定团队平均多10.5% Token，主要来自 Supervisor；两者工具调用和修复次数相同。
因此在已经确定必须做表格理解和多步计算的 FinQA 任务上，固定两角色图是当前更稳妥的默认路径。
Supervisor 更适合任务形态不确定、角色可裁剪的 FinanceBench 或真实风险分析请求。

## 失败处理

首次动态运行有1题因最终汇总返回空程序而触发结构校验失败。该题是公开数据中的 OCR/年份异常；
计算 Agent 可能已有程序，但汇总节点按字面年份拒答。现已允许汇总暂时返回空程序，并在存在本地
执行通过的计算 Agent 程序时由 Harness 覆盖回该程序；若不存在有效程序，官方评分仍按错误计分。
重试后运行成功率恢复为100%，没有放宽官方正确性标准。

## 当前决策

1. 多步 FinQA 默认路由到固定表格+计算图，不额外调用 Supervisor；
2. 简单 FinQA 默认单 Agent，避免6倍以上 Token 成本；
3. 正式 Gate 对 C/D 复杂子集各重复3次，再判断5个百分点差异是否稳定；
4. 当前20题结果只用于开发决策，不写入简历为最终指标。
