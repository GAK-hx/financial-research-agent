# V4FinBench 公开风险标签接入方案

## 选型结论

A 规则/统计路径的正式公开风险 Benchmark 采用 V4FinBench，UCI Polish Companies Bankruptcy
与 Taiwanese Bankruptcy Prediction 仅作为小数据回归备选。

V4FinBench 覆盖约110.7万条 company-year、20.4万家公司、131个财务与非财务特征、2006—2021
年和6个预测期限。标签是偿债、盈利和流动性同时恶化的复合财务困境状态，正类比例约
0.19%—0.36%。其公司分组、国家分层五折协议比随机切分更适合防止公司泄漏，也能检验真实的
极度不平衡问题。

来源：

- 论文：https://arxiv.org/abs/2605.10896
- 复现仓库：https://github.com/genwro-ai/V4FinBench
- 公开数据：https://www.kaggle.com/datasets/sebastiantomczak10/v4-group-corporate-bankruptcy/data

## 使用范围

1. 主任务使用 `company_years_h2.parquet`，对应论文 `h=1` 的一年期前瞻风险；
2. `h=0` 只验证当前期规则与标签定义一致性，不作为前瞻预测成绩；
3. 后续资源允许时扩展 `h=2` 和 `h=3`，观察风险提前量；
4. 不让 LLM 直接替代强表格模型预测破产概率；模型输出风险候选，Agent 负责证据复核、反证、
   归因和报告；
5. V4FinBench 主要评估偿债流动性、盈利现金流和部分资产质量，不声称覆盖披露审计风险。

## 公平切分

严格复用官方协议：

- 五折；
- `random_state=42`；
- 同一公司全部记录必须在同一折；
- 保持国家结构；
- 每轮一个验证折、下一个测试折、其余三个训练折；
- 决策阈值只能在验证折选择，测试折只评一次；
- 缺失值填补、缩放、特征选择和类别权重只能在训练折拟合。

## A 路径对照

| 配置 | 方法 | 目的 |
|---|---|---|
| A0 | 当前期三维复合规则 | 校验标签口径，不作为前瞻预测基线 |
| A1 | 类别加权 Logistic Regression | 可解释统计基线 |
| A2 | 固定参数 LightGBM | 非线性强基线；采用公开基线参数空间中的单组配置，不逐折调参 |
| B | A2候选 + 单风险复核Agent | 测量证据复核的增量与成本 |
| C | 固定风险域团队 | 测量多方法并行本身的增量 |
| D | 动态Supervisor + Evaluator | 测量动态裁剪和定向修复的增量 |

Agent 不修改 A1/A2 的测试标签或预测概率，只能输出确认、降级、替代解释、证据不足和风险报告。

## 指标

极度不平衡下不使用 Accuracy 作为主指标：

- PR-AUC：主排序指标；
- ROC-AUC：与论文参考结果对齐；
- F1：阈值在验证折选择；
- Recall@固定Precision、Precision@固定Recall：对应重大风险漏报/误报取舍；
- Brier Score、校准曲线和ECE：验证概率是否可解释；
- 各国家、行业、公司规模和预测期限的分组结果；
- 五折均值、标准差和每折原始结果，不只报告最佳折。

## 数据与资源预算

Kaggle 元数据显示完整数据集约6.8 GB，直接全量下载并解压可能突破当前新增数据10 GiB上限，
因此禁止下载全部7个Parquet。

暂定只下载 `company_years_h2.parquet`：

- 下载前先读取单文件大小；超过3 GiB则暂停并重新评估；
- 原始文件只保存一份，不复制出五份训练集；折号作为一列或独立小型映射保存；
- DuckDB/PyArrow按列读取，经典模型矩阵按折构建；
- 预计最低4 vCPU、8 GiB RAM；若单文件或峰值内存超过预算，改用分批训练或Spark，不静默交换到磁盘；
- 产物仅保存折号、模型、预测、指标和必要解释，不保存重复全量中间表；
- 不引入TabPFN或本地LLM训练，它们需要额外GPU和模型存储，不属于当前Agent项目的必要范围。

实测 `company_years_h2.parquet` 为820,175,115字节（782.18 MiB），在4 CPU、6 GiB限制的
Docker容器中完成官方五折映射和类别加权Logistic Regression五折基线。下载入口支持Range
断点续传，只校验文件大小与Parquet边界，不计算额外哈希。

- 五折测试预测共996,500行，`row_index`去重后仍为996,500，所有样本恰好作为测试样本出现一次。

## A1实测结果

类别加权Logistic Regression使用131个数值/布尔特征；缺失值中位数、标准化、Platt概率
校准和F1阈值均只在训练折或验证折拟合，测试标签不参与训练、校准或选阈值。

| 指标 | 五折均值 | 标准差 |
|---|---:|---:|
| PR-AUC | 0.03829 | 0.00232 |
| ROC-AUC | 0.91016 | 0.00338 |
| F1 | 0.09174 | 0.00449 |
| Precision | 0.05857 | 0.00209 |
| Recall | 0.21275 | 0.02268 |
| Recall@Precision 5% | 0.33702 | 0.03773 |
| Brier Score | 0.00315 | 0.00012 |
| ECE（10 bins） | 0.00042 | 0.00015 |

数据正类率约0.306%，因此PR-AUC约为随机基准的12.5倍；但10% Precision仅个别折可达到，
该Precision下的平均Recall仅0.38%，说明A1适合作为可解释排序基线，不能被包装成高精度重大风险识别器。

## A2实测结果

LightGBM采用公开基线搜索空间中的固定配置（200棵树、学习率0.05、无限制树深），没有进行
逐折参数搜索。概率校准和F1阈值仍只使用验证折，测试标签保持不可见。

| 指标 | A1均值 | A2均值 | 相对改善 | A2胜出折数 |
|---|---:|---:|---:|---:|
| PR-AUC | 0.03829 | 0.06384 | 66.7% | 5/5 |
| ROC-AUC | 0.91016 | 0.93293 | 2.5% | 5/5 |
| F1 | 0.09174 | 0.13107 | 42.9% | 5/5 |
| Precision | 0.05857 | 0.08903 | 52.0% | 5/5 |
| Recall | 0.21275 | 0.25363 | 19.2% | 3/5 |
| Recall@Precision 5% | 0.33702 | 0.61234 | 81.7% | 5/5 |

A2已满足项目所需的稳定、明显改善：核心排序、F1和固定Precision下的Recall均在五折全部胜出。
但ECE没有改善，整体Recall也只在3/5折胜出，因此不表述为“所有指标全面提升”，也不继续调参
追求简历数字。A1、A2各996,500条测试预测均覆盖全量样本且每行恰好出现一次。

## 与四类风险 Agent 的衔接

- 偿债流动性 Agent：读取负权益、负债覆盖和流动性候选；
- 盈利现金流 Agent：读取 EBITDA、盈利能力和现金转换候选；
- 资产质量 Agent：读取资产结构、减值代理和异常变化候选；
- 披露审计 Agent：继续使用公告/审计文档链路，V4FinBench 不为该域提供准确率标签；
- Evaluator：检查候选、证据、替代解释和缺失，不接触测试标签。
