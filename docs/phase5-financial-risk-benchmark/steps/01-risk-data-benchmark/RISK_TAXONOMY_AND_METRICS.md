# 风险口径与指标字典 v1

## 1. 口径边界

分析单元固定为 `公司 + 报告期 + 分析截止日 + 数据快照`。系统识别的是需要复核的财务风险信号，
不是违约概率、股价预测或投资评级。单个比率触发一般只产生 `WATCH`；只有达到升级阈值且具备最低证据，
或存在非标准审计意见、重大更正等强事件时，才允许产生 `ESCALATE`。

四类风险分别为：

1. 偿债与流动性：短期偿债资源是否覆盖到期义务；
2. 盈利质量与现金流：账面利润是否由现金流支持；
3. 资产质量与减值：应收、存货、商誉及减值是否出现异常；
4. 财务披露与审计：更正、监管问询和审计意见是否构成披露风险。

## 2. 事实、信号与结果分离

- `RiskFact`：来自报表或公告的可追溯事实，不能包含模型推断；
- `RiskMetricDefinition`：公式、输入、单位、窗口、缺失策略与阈值；
- `RiskCandidate`：规则或统计模型发现的待复核信号；
- `RiskAssessment`：Agent在指定截止日给出的业务分析结果，仅用于演示和运行记录，不作为Benchmark标签；
- `Outcome`：分析截止日之后发生的可观察事件，只用于回放，不进入输入。

代码中的唯一机器可读口径为
`src/financial_research_agent/risk/risk_metrics_v1.json`。本文件解释原则，不能单独修改数字而不升级 Registry。

## 3. v1 指标

| 类别 | 指标 | 主要输入 | 初始研究阈值 | 最低证据 |
|---|---|---|---|---|
| 偿债 | 流动比率 | 流动资产、流动负债 | `<1.5` 关注，`<1.0` 升级候选 | 财务事实 |
| 偿债 | 现金短债比 | 现金、短期有息债务 | `<1.0` 关注，`<0.5` 升级候选 | 财务事实+附注 |
| 偿债 | 经营现金流/流动负债 | 年度经营现金流、年末流动负债 | `<0.2` 关注，`<0` 升级候选 | 财务事实 |
| 盈利质量 | 经营现金流/净利润 | 年度经营现金流、年度归母净利润 | `<0.8` 关注，`<0.3` 升级候选 | 财务事实 |
| 盈利质量 | 应计利润/资产 | 利润、经营现金流、平均资产 | `>5%` 关注，`>10%` 升级候选 | 财务事实 |
| 盈利质量 | 利润现金流连续背离 | 利润、经营现金流 | 3期中2期关注、3期升级候选 | 财务事实 |
| 资产质量 | 应收与收入增速差 | 应收、收入同比 | `>15pp` 关注，`>30pp` 升级候选 | 财务事实 |
| 资产质量 | 存货与收入增速差 | 存货、收入同比 | `>15pp` 关注，`>30pp` 升级候选 | 财务事实 |
| 资产质量 | 商誉/资产 | 商誉、总资产 | `>10%` 关注，`>20%` 升级候选 | 财务事实+附注 |
| 资产质量 | 减值/资产 | 年度减值、平均资产 | `>2%` 关注，`>5%` 升级候选 | 财务事实+附注 |
| 披露审计 | 非标准审计意见 | 审计报告 | 命中即升级候选 | 审计报告 |
| 披露审计 | 财务更正/重大修订 | 公司公告 | 命中即升级候选 | 公司公告 |
| 披露审计 | 财务类监管问询 | 监管公告 | 命中即关注 | 监管公告 |

阈值是建立基线所需的初始假设，不是行业通用真理。Step 01-D 必须按行业和规模报告分布；金融机构
不能直接套用普通工商企业的流动比率与负债率口径。

v1 只使用年末年报中的完整年度累计流量和年末/年初资产存量。当前来源虽返回季度累计数据，但缺少可验证的
历史修订快照，因此本阶段不把它包装为严格季度 TTM；季度 TTM 在后续积累四个可复现季度快照后升级指标版本。

## 4. 缺失语义

- `NOT_DISCLOSED`：该公司/报告明确没有披露对应字段；
- `NOT_AVAILABLE_FROM_SOURCE`：当前来源或接口没有提供，不能推断为公司未披露；
- `REJECTED_BY_QUALITY`：源值存在但未通过类型、单位、日期或一致性检查；
- `PRESENT`：可使用的事实，数值 0 是合法值而不是缺失值。

只有明确布尔事件可以采用“未检出不等于命中”的策略。比率输入缺失时必须跳过指标或把案例降级为
`INSUFFICIENT_DATA`，不得补 0。

## 5. 时间边界

每条事实同时保存：

- `source_published_at`：市场何时可以看到；
- `observed_at`：本系统何时抓到；
- `report_period`：事实属于哪个财务期间；
- `revision_no` 与内容哈希：同一报告后续修订的版本。

回放时先过滤 `source_published_at <= as_of_date`，再过滤 `observed_at <= system_cutoff`，然后在同一
公司、报告期、指标内选择当时可见的最新修订。后续确认事件只进入标签结果区。

## 6. 版本变更规则

- 修改公式、输入字段、单位、窗口、缺失策略或阈值必须产生新版本；
- 单纯补充解释文字可不升级，但要记录 Git 变更；
- 业务回放记录固定其Registry版本，不自动跟随最新版本；
- 指标阈值变更必须在运行前版本化，不能根据个别演示结果倒推修改。
