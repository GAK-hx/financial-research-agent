# Step 03分步实施计划

## 原则

- 一次完成一个工作包，每个工作包只做一次末尾集中验证；中途仅做导入或单案例可行性检查；
- 安全与隔离项保持硬门槛：未来数据泄漏、跨租户读取、未授权Tool、重复终态和任务丢失必须为0；
- 性能只要求相对基线稳定且明显改善，不为简历目标追分；简历数字低于实测；
- 自有公司数据只验证流程、性能和可重放性，不报告风险Precision、Recall或F1；
- 不建立私有Holdout或人工标签，效果只引用公开Benchmark；
- 默认全部在Docker执行，K8s本地集群只证明Manifest与故障恢复，不冒充生产集群。

## 03-A 历史回放与增量边界

目标：在同一批冻结事实之上重建多个历史`as_of_date`，证明PIT筛选、特征、候选和数据快照可重放。

实现：

1. 以2022-06-30、2023-06-30、2024-06-30、2025-06-30、2026-06-30为默认回放点；
2. 来源时间按`source_published_at <= as_of_date`过滤，系统时间按当前冻结回填批次截止；
3. 每个回放点保存特征、候选、状态分布、跨期新增/变化和PIT泄漏计数；
4. 明确这是`source-time backfill replay`，不是当年真实系统知识快照；
5. 计算相邻回放点受影响的自然键比例，为后续增量重算提供输入；
6. 子Agent边际贡献引用Step 02公开同题消融，不在自有数据上制造正确率标签。

资源预算：读取约15.6万事实和公告数据；5个回放点预计小于20万特征行和6万候选行；
Docker限制4 CPU / 6 GiB，新增产物预计小于1 GiB。

验收：5个回放点全部成功、PIT泄漏0、主键重复0、相同配置重跑结果行数与状态分布一致。

## 03-B 公共Artifact、缓存与多用户

目标：查询、分析、输出分离；同公司/报告期/数据版本的公共分析跨用户复用，用户报告严格隔离。

实现：

1. PostgreSQL保存Job和最终事实，Redis保存single-flight、热缓存和可重建状态；
2. `RetrievalSnapshot`与`RiskAssessmentArtifact`使用公共键，`UserReport`使用tenant/user键；
3. 同批交叉股票查询合并检索与分析，新增数据只使受影响Artifact失效；
4. 1/5/20/50用户逐级执行，每人4～5家公司、总体约20家公司、约60%重叠；
5. 分别记录冷缓存、热缓存、增量更新的p50/p95/p99、外部调用、排队和命中率。

资源预算：PostgreSQL与Redis各1个本地容器，API/Worker各1～2副本；Docker总预算优先控制在
8 CPU / 12 GiB以内。模型调用先以冻结响应验证并发，再对最小在线样本使用DeepSeek Flash。

验收：跨租户读取0、重复终态0、任务丢失0；热缓存延迟和重叠外部调用相对冷基线有稳定、明显下降。

## 03-C Spark/Iceberg增量与恢复

目标：证明全量、增量、分区裁剪、回填和失败恢复，而不是扩大业务功能。

实现：

1. 使用明确标记的合成数据扩展到500万行，资源允许后再到1000万行；
2. 对比全量重算与仅受影响公司/期间的增量重算；
3. 测量Iceberg分区裁剪、扫描行数/字节、Snapshot与小文件整理；
4. 注入批任务中断并验证重跑无重复写入；
5. 输出表血缘、质量规则和运行手册。

资源预算：默认4～6 CPU / 8 GiB；新增合成数据和中间产物不超过5 GiB，接近上限先清理可重建产物。

验收：增量和分区裁剪均明显降低扫描量；相同批次重跑不增加业务主键，失败后可恢复。

## 03-D Docker/K8s与最终交付

目标：完成容器角色拆分、K8s Manifest、故障演练和三类岗位文档。

实现：

1. API、Worker、评测、迁移分别运行；湖初始化使用独立命令；镜像非root、只读根文件系统、健康检查；
2. Kind三节点是共享本机资源的逻辑节点，不声明为三台生产机器；
3. Deployment/Job/CronJob、ConfigMap/Secret、requests/limits、HPA、PDB、NetworkPolicy和探针齐全；
4. 演练滚动更新、Worker驱逐、Job重试、Redis降级和SSE重连；
5. 生成Agent、数据分析、数据开发、部署和演示文档；
6. 完成Secret、许可证和仓库历史检查；GitHub继续保持私有，公开必须再次获得用户授权。

验收：安全硬门槛全部通过；性能报告完整；Manifest可执行；本地演练无重复终态和跨租户问题。
