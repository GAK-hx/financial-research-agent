# 11 设计审核清单

请优先确认下列问题。确认后再把文档转成编码任务。

## A. 产品与范围

- [ ] 第一版以单次研究任务为主，不做多轮长期对话；
- [ ] 正式支持行情、研报、综合分析，财务按数据可用性加入；
- [ ] 不做自动交易和写操作；
- [ ] 不做多Agent角色系统。

## B. 数据管理

- [x] 默认使用前复权日线；
- [x] 第一版股票池为600519、300750；
- [x] Raw API响应开发阶段按批次保存Parquet；
- [x] 质量失败采用行级隔离，批次Warning；
- [ ] 是否在第一步建立metadata namespace；
- [ ] 财务域第一版做到什么范围。

## C. 记忆管理

- [ ] 第一步只实现Run/Working/Evidence Memory；
- [ ] 第二步是否需要Session多轮记忆；
- [ ] 长期记忆只保存用户偏好，不保存市场事实；
- [ ] 第一步Run调试结果保存文件还是SQLite。

## D. Agent编排

- [ ] 第一步使用固定标准轨迹+模型结构化计划；
- [x] 第一步不启用动态Replan；
- [x] Planner允许规则降级，正式报告失败明确报错；
- [ ] 是否只流式返回阶段状态。

## E. 工具与Evidence

- [ ] 第一阶段只注册只读工具；
- [ ] Indicator Tool是否复用Market结果；
- [ ] Evidence Statement使用确定性模板；
- [ ] 报告每个关键Claim必须引用Evidence。

## F. RAG

- [ ] 第一阶段继续500/50分块；
- [x] 不加入Reranker，先测召回基线；
- [x] 先使用6份研报闭环；
- [ ] 报告日期缺失时允许索引但标Quality Flag。

## G. 可靠性与评测

- [x] 工具失败允许生成带缺失说明的部分报告；
- [x] 规则模板报告不作为正式输出；
- [ ] 先使用20题最小评测集；
- [ ] LLM Judge只作辅助，不替代代码Validator。

## H. 部署

- [x] 第一步不常驻Kafka/Flink；
- [x] 不引入ClickHouse/HDFS/MinIO；
- [x] 项目主体采用Docker优先部署；
- [ ] 研报是否从旧项目迁移；
- [ ] 第二步再决定PostgreSQL、Worker和Trace平台。

## 审核输出

审核后建议形成一份`DECISIONS.md`，为每个选项记录：决定、原因、影响阶段和日期。只有被接受的设计才进入Issue/任务清单和代码实现。
