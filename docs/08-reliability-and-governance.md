# 08 可靠性与治理

## 1. 目标

可靠性不等于永不失败，而是失败有边界、可解释、不编造、不无限运行。

## 2. 预算

第一步默认：模型3次、工具8次、任务6个、并发4、总时长60秒、单工具重试2次、报告修订1次。

第二步Budget Manager统一记录和扣减Token、工具次数、时间和成本。

## 3. 错误分类

- ValidationError：参数/Schema错误；
- DataNotFound：真实无数据；
- DataStale：数据日期不满足；
- ToolTimeout：工具超时；
- RateLimit：外部限流；
- DependencyUnavailable：Milvus/模型不可用；
- PolicyDenied：工具或参数被策略拒绝；
- InternalError：程序缺陷。

## 4. 处理策略

- 参数错误：修正一次；
- 临时网络/限流：指数退避；
- 数据为空：明确缺失，不扩展成无关数据；
- Milvus失败：可返回无研报的部分报告；
- Planner模型失败：使用规则计划；正式报告模型失败：明确失败，不使用模板冒充正式报告；
- 预算耗尽：停止新任务并说明未完成部分；
- 内部错误：记录Trace，任务失败。

## 5. 幂等与恢复

第一步只保证采集批次幂等和单次Run不重复调度同一task_id。

第二步通过Run/Task Store实现`run_id + task_id`幂等、状态持久化、重启恢复和已完成结果复用。

## 6. Completion Checker

第二步正式引入，但第一步Validator已执行其核心子集：必要任务状态、数据日期、Evidence引用、数字一致、风险章节。

## 7. 数据与模型治理

- Prompt和指标公式版本化；
- 数据源和复权口径进入Evidence；
- 模型版本进入Run metadata；
- 模拟域不能在正式模式查询；
- 报告包含非投资建议说明；
- 未来副作用工具需要人工审批。

## 8. 已确认与待审核决策

- 已确认：部分工具失败允许返回报告，但必须列出缺失维度和Validation Warning；
- 已确认：规则模板报告不作为正式输出；
- 第一步总超时60秒是否足够？建议先测量后调整，不先扩大。
